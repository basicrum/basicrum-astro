## Verdict

Both loader modes are correctly integrated into the local test setup.
The renamed options are exercised with the real vendored loaders and
Boomerang bundle. Non-consent intentionally starts immediately without a
consent decision; consent waits for the site's consent manager.

- `npm test` includes `npm run test:browser`. The latter runs both projects
  declared in `playwright.config.js`: `tests/browser` and `tests/e2e`.
  `npm run test:e2e` selects only the readable loader workflows. CI and the
  Release workflow call the same combined browser command.
- The fixture server uses `brumSiteId`, `beaconEndpoint` and `non-consent`.
  Beacon assertions prove the configured site identifier reaches the wire;
  intercepted and loopback collector traffic exercises the endpoint setting.
  Loader-specific callbacks and request counts distinguish the two modes.
- Consent denial, grant, withdrawal, re-grant after reload, queued sends,
  download races, full-page navigation and query stripping have meaningful
  coverage. Cookie deletion is supported by seeded positive controls and
  an integration test using host-only and parent-domain cookies.
- Test collection stays on the intercepted `collector.basicrum.test` host
  or the real loopback collector. Readiness follows static fixture builds
  and live SSR/dev probes. The shared unload collector tests run serially.
- Codex inspected ports 43211-43221 after the completed run and found no
  remaining listeners. Failure and interruption cleanup paths were not
  separately tested, and no cleanup defect was established.
